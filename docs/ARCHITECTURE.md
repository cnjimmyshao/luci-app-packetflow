# Architecture

Packet Flow is a read-only LuCI inspector for the *effective* Linux/OpenWrt networking state.

## Data sources

- `nft -j list ruleset`: Netfilter base chains, hooks, priorities and mark-setting expressions.
- `ip -j rule show`: RPDB policy rules and priorities.
- `ip -j route show table all`: all kernel routing tables.
- `ip -j link show`: egress/ingress interfaces.
- `ip -j route get`: read-only kernel route decision probe.

The UI reads live kernel state rather than only UCI configuration. This lets it observe state generated by fw4, pbr, mwan3, VPN packages and custom software.

## Pipeline model

```text
Ingress
  -> Netfilter hook/base-chain priority
  -> packet / connection marks
  -> RPDB (ip rule)
  -> routing table
  -> egress interface
```

The relationship graph joins RPDB rules to visible routing tables and default egress interfaces. It is deliberately presented as a model: locally generated traffic, bridging, conntrack, flow offload, XDP/tc, tunnelling and other kernel paths can change actual traversal.

## Route Trace

Route Trace invokes `ip route get` with validated argv. It can include source address, fwmark and input interface. This asks the kernel for its routing decision without sending a packet.

It is **not** a full nftables replay. Future live packet tracing must clearly distinguish observed trace events from inferred relationships.

## Diagnostics

The inspector currently checks for structural problems such as:

- policy rules referring to routing tables with no visible routes;
- routes using interfaces reported DOWN;
- multiple base chains sharing a hook priority, surfaced as an ordering-awareness notice.

Further diagnostics can be added without changing the read-only safety model.

## Safety model

v0.x is intentionally read-only. It must not mutate nftables, ip rules, routes, addresses or interfaces. Route Trace validates user input and passes arguments as argv rather than constructing shell strings.

See [SECURITY.md](SECURITY.md) and [TESTING.md](TESTING.md).

## Scope status

Implemented:
1. Live-state inventory
2. RPDB → route-table → egress relationship view
3. Initial conflict/structural diagnostics
4. Read-only route decision trace
5. CI static/safety checks

Future work focuses on richer mark attribution, real nftables trace integration, flow-offload/conntrack visibility and visualization polish rather than turning the inspector into a network configuration editor.
